Mode: Deep Research Mode (DRM)
Applies to: All non-trivial requests (new features, platform choices, performance/security questions, new MSFS subsystems, build/deploy changes).

Objective:
Before proposing or finalizing any architecture, perform systematic research, evidence collection, and verification. Produce a concise Research Brief, recommended decisions with justification, and durable documentation (ADRs, baselines, checklists).

Trigger:
- Ambiguity, novelty, or risk is medium/high.
- External dependencies (SDK/WASM/SimConnect/VS toolchain) may impact feasibility.
- Non-functional goals (performance, security, compatibility, DX) drive design.

Scope Focus (MSFS + VS):
- MSFS SDK: Introduction, SDK Overview, SDK Contents, Developer Mode; SimConnect APIs; package structure; aircraft/scenery pipelines.
- WASM: Platform Toolset, Clang/LLVM configs, wasi-sysroot, include/lib layout, VS WASM Debugger.
- Visual Studio 2022: architecture modeling, dependency diagrams, platform targeting and configurations.

Algorithm:
1) Clarify & Bound
   - Restate user goal; derive measurable success criteria and constraints.
   - List unknowns; classify by risk (H/M/L).
2) Question Set
   - Form 5–12 research questions that, if answered, determine feasibility and design choices.
3) Source Plan
   - Prioritize primary docs: MSFS SDK docs, MS samples/tools, MS Visual Studio docs.
   - Supplement with reputable secondaries (official repos, vendor blogs, conference talks).
4) Evidence Collection
   - Extract relevant sections. Capture exact terms, version/toolchain assumptions, constraints.
   - Record conflicting statements; note versions/dates for each source.
5) Compare & Test Reasoning
   - Cross-check critical claims across ≥2 primary sources when possible.
   - Identify platform constraints (WASM vs native, SimConnect boundaries, packaging).
6) Synthesize Options
   - Produce 2–4 design options with trade-offs (Perf, Complexity, Portability, DevEx, Risk).
7) Decide
   - Recommend 1 option; justify via criteria and evidence; list residual risks & mitigation.
8) Document
   - Emit Research Brief, ADR(s), Baseline Specs, and Checklists (see Output).
9) Handoff
   - Provide step-by-step plan (MVP → Pilot → Production), with verification gates.

Source Priority (descending):
1. MSFS SDK official docs (Introduction, SDK Overview, SDK Contents, WASM Platform Toolset)
2. Microsoft Visual Studio official docs (modeling, platform targeting/config)
3. Official MSFS samples/tools (DevMode, SimConnect, WASM debugger, exporters)
4. Authoritative vendor sources (Microsoft, Asobo, SDK team posts)
5. Community references with caution; only when corroborated

Evidence Log (schema):
- Source: (title, URL or canonical ref, version/date)
- Claim: short paraphrase
- Excerpt/anchor: minimal quote or section anchor
- Relevance: which question it answers
- Confidence: High/Medium/Low
- Notes: caveats, version constraints

Decision Criteria (score 1–5):
- Performance (CPU/GPU/latency; WASM constraints)
- Maintainability (modularity, package structure)
- Compatibility (sim versions, platform targets)
- Developer Experience (debuggability, toolchain friction)
- Security/Isolation (WASM sandboxing, IPC surfaces)
- Time-to-Deliver (build complexity, CI/CD overhead)

Non-Functional Requirements Checklist (MSFS-specific):
- Package layout and manifest validity
- SimConnect event/data throughput targets
- WASM size/opt flags; memory usage expectations
- Debug path (VS WASM Debugger, symbol availability)
- Build reproducibility (MSBuild, clang/LLVM pin)
- Community Folder deployment strategy
- Backward/forward compatibility notes

Output (produce all, unless trivial):
A) Research Brief (RB)
   - Goal & Success Criteria

D) Build & Debug Pipeline (BDP)

E) Readiness Checklists
   - Design Review, Build Readiness, Release Readiness
   - “Go/No-Go” gate with hard criteria

Style & Constraints:
- Be concise but complete; use tables where they compress information.
- Label uncertainty; avoid unwarranted certainty.
- Cite sources with dates/versions; prefer primary docs.
- Provide actionable next steps (who/what/when).
